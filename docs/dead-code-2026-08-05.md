## 5. Fällorna

### 5.1 Barrel-filer — den kända (bekräftad, 21 st)

21 `index.ts` med noll importörer. Var och en importerar sitt underträd, så en vanlig
`grep "from '.*Foo'"` hittar barreln och rapporterar "har importör". `hooks/index.ts`
(58 rader) håller ensam **~2 650 rader** vid liv för importsökningen.

**Konsekvens för ordningen:** barrels måste raderas i steg 1. Skriptets `--steg=barrels`
gör exakt det, och nåbarhetsanalysen körs om mellan stegen.

### 5.2 CSS `@import` — ny fälla, funnen under arbetet

Första versionen av skriptet parsade bara JS/TS-importer. Den klassade
**`src/styles/accessibility.css` som död**. Filen importeras från `src/index.css:19`
med CSS:ets eget `@import`, som ingen JS-parser ser.

Hade passet körts hade **fokusringar, skip-links och skärmläsarklasser försvunnit** —
en WCAG-regression i en portal vars hela premiss är tillgänglighet, orsakad av ett
städskript.

Åtgärdat: parsern kan `@import "…"` och `@import url("…")`. Efter fixen gick
`accessibility.css`, `tokens.css` och `dashboard-grid.css` från "död" till levande,
medan `App.css`, `design-system.css` och `animations.css` förblev döda — de tre nämns
bara i **en kommentar** i `index.css:8-10`, de importeras inte.

> **Generell lärdom:** CSS-grafen är inte JS-grafen. Ett `@import` i CSS, en
> `<link>` i `index.html` och en `url()` i en stilregel är alla kanter som en
> importsökning över `.ts`-filer aldrig ser.

## 6. Skriptet

`client/scripts/dead-code.cjs`

```bash
node scripts/dead-code.cjs                  # översikt + siffror (torrläge)
node scripts/dead-code.cjs --lista          # varje post med grupp och motivering
node scripts/dead-code.cjs --grupp=RADERA   # filtrera
node scripts/dead-code.cjs --json           # maskinläsbart, inkl. olösta importer
node scripts/dead-code.cjs --tak            # skuldfördelning levande/död (~2 min)
node scripts/dead-code.cjs --namngrind      # visa vad grinden skulle blockera
node scripts/dead-code.cjs --skriv          # UTFÖR
node scripts/dead-code.cjs --skriv --steg=barrels   # bara ett steg
```

### 6.1 Säkerhetsmodellen (samma som `apply-expansions.cjs`)

1. **Torrläge är default.** Ingenting flyttas eller raderas utan `--skriv`.
2. **`--skriv` kräver rent arbetsträd.** Skriptet kör `git status --porcelain` och
   avbryter med exit 1 om något är ocommittat. **Verifierat 2026-08-05:** körningen
   avbröts, `git status` visade 0 raderade filer efteråt.
3. **Namngrinden måste vara öppen.** Varje kandidat söks över hela repot utanför
   `client/src`. En träff blockerar hela passet — man klassar om till UTRED, man
   forcerar inte.
4. **Endast RADERA och ARKIVERA rörs.** UTRED och BEHÅLL passerar aldrig.
5. **`git rm` / `git mv`** — inte `fs.unlink`. Historiken följer med, allt är i
   indexet och går att ångra med `git restore --staged`.
6. **Stegvis.** `barrels → hooks → komponenter → övrigt`, med `--steg=` för att köra
   ett i taget och köra grindarna emellan.

### 6.2 Vad skriptet **inte** gör

- Det ändrar inte `CLAUDE.md`, `eslint.config.js`, `check-design-debt.cjs` eller
  `typecheck-critical.cjs`. Följdändringarna är manuella och listade i §7.
- Det sänker inte taken. Det mäter dem (`--tak`) — sänkningen är ett medvetet beslut.
- Det rör inte `package.json` (C18: `svgo`, `xlsx`, `pdf-lib`, `papaparse`).
